## Architecture Flow

```
User pastes company "About Us" text
            ↓
Backend (FastAPI) receives raw text
            ↓
Text chunked into ~300 word overlapping segments
(shorter chunks = more precise value extraction)
            ↓
Each chunk embedded via Gemini text-embedding-004 → 768-dim vector
Vectors + chunk text stored in PostgreSQL via pgvector
            ↓
Five parallel semantic retrieval queries fired:
  Query 1: "What are the core values of this company?"
  Query 2: "What is the mission and long-term vision?"
  Query 3: "What kind of person thrives in this culture?"
  Query 4: "What does this company believe about work and people?"
  Query 5: "What are the behavioural expectations at this company?"
            ↓
For each query → embed → retrieve top 3 most relevant chunks via cosine similarity
            ↓
Serper API fires web search for:
  "[company name] company culture research"
  "companies with [extracted vision keywords] culture studies"
  → Returns real URLs + snippets (no hallucination)
            ↓
Gemini 2.5 Flash generates:
  Section 1: Company Culture Report (grounded in retrieved chunks)
  Section 2: Values You Need To Thrive (grounded in retrieved chunks)
  Section 3: Research Insights (grounded in real Serper search results)
  Section 4: 8-question diagnostic quiz (generated from retrieved values)
            ↓
Quiz questions + scoring rubric stored in PostgreSQL
            ↓
Frontend displays:
  - Full culture report with chunk citations
  - Research section with real URLs as sources
  - Interactive 8-question quiz
  - Spider chart rendering scores across 5 dimensions
  - History of past company analyses
```

## The 5 Spider Chart Dimensions

These are extracted dynamically per company but map to these universal axes:

1. **Innovation Orientation** — how much does this company value creative risk-taking?
2. **Collaboration vs Autonomy** — team-first or independent ownership?
3. **Mission Alignment** — how values-driven vs commercially driven?
4. **Pace & Adaptability** — fast-moving startup energy or structured stability?
5. **People Philosophy** — how much does this company invest in its people?

Quiz questions are generated by Gemini to test the user on these 5 dimensions, calibrated to the specific company's retrieved values.

## Database Schema

### Table: companies
```sql
CREATE TABLE companies (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255),
    raw_about_text TEXT NOT NULL,
    extracted_values JSONB,        -- AI-extracted value keywords
    created_at TIMESTAMP DEFAULT NOW()
);
```

### Table: chunks
```sql
CREATE TABLE chunks (
    id SERIAL PRIMARY KEY,
    company_id INTEGER REFERENCES companies(id) ON DELETE CASCADE,
    chunk_index INTEGER NOT NULL,
    chunk_text TEXT NOT NULL,
    embedding vector(768)
);
```

### Table: reports
```sql
CREATE TABLE reports (
    id SERIAL PRIMARY KEY,
    company_id INTEGER REFERENCES companies(id) ON DELETE CASCADE,
    culture_report TEXT,
    values_to_thrive TEXT,
    research_insights TEXT,        -- includes real URLs from Serper
    quiz_questions JSONB,          -- array of {question, options, dimension, correct_weight}
    created_at TIMESTAMP DEFAULT NOW()
);
```

### Table: quiz_results
```sql
CREATE TABLE quiz_results (
    id SERIAL PRIMARY KEY,
    report_id INTEGER REFERENCES reports(id) ON DELETE CASCADE,
    dimension_scores JSONB,        -- {innovation: 7, collaboration: 4, ...}
    overall_fit_score INTEGER,
    created_at TIMESTAMP DEFAULT NOW()
);
```

## Serper API Integration

Get free key at serper.dev → 2,500 free searches/month.

```python
# services/searcher.py
import httpx
import os

async def search_company_research(company_name: str, values: list[str]) -> list[dict]:
    headers = {"X-API-KEY": os.getenv("SERPER_API_KEY")}
    
    queries = [
        f"{company_name} company culture research",
        f"{' '.join(values[:3])} workplace culture studies statistics"
    ]
    
    results = []
    for query in queries:
        response = await httpx.post(
            "https://google.serper.dev/search",
            json={"q": query, "num": 3},
            headers=headers
        )
        data = response.json()
        for item in data.get("organic", [])[:3]:
            results.append({
                "title": item["title"],
                "snippet": item["snippet"],
                "url": item["link"]
            })
    
    return results
```

## Spider Chart Component

Use recharts RadarChart. Install: `npm install recharts`

```jsx
// components/SpiderChart.jsx
import { RadarChart, PolarGrid, PolarAngleAxis, Radar, ResponsiveContainer } from 'recharts';

export default function SpiderChart({ scores }) {
  const data = [
    { dimension: 'Innovation', score: scores.innovation },
    { dimension: 'Collaboration', score: scores.collaboration },
    { dimension: 'Mission', score: scores.mission },
    { dimension: 'Pace', score: scores.pace },
    { dimension: 'People', score: scores.people },
  ];

  return (
    <ResponsiveContainer width="100%" height={400}>
      <RadarChart data={data}>
        <PolarGrid />
        <PolarAngleAxis dataKey="dimension" />
        <Radar dataKey="score" stroke="#6366f1" fill="#6366f1" fillOpacity={0.3} />
      </RadarChart>
    </ResponsiveContainer>
  );
}
```

## Chunking Strategy Change

Original plan used 500-word chunks. This project uses **300-word chunks** with 50-word overlap.

Reason: Company About Us pages are short (200–800 words typically). 500-word chunks would produce only 1–2 chunks with no meaningful retrieval differentiation. 300-word chunks with overlap gives you 3–5 retrievable segments from a typical About Us page, making the RAG pipeline actually meaningful rather than cosmetic.

## Known Risks

1. **Short About Us text = too few chunks** — If user pastes very short text (<150 words), chunking produces 1 chunk. RAG retrieval becomes meaningless. Solution: set minimum input length of 150 words and show a warning if under.
2. **Serper quota** — 2,500 searches free. Each analysis fires 2 searches. That's 1,250 analyses before quota hits. More than enough for evaluation + demo.
3. **Gemini JSON output malformed** — Gemini sometimes returns JSON with extra text around it. Always wrap JSON.parse in try/catch. Strip markdown fences before parsing.
4. **CORS failure in production** — Configure with exact Vercel URL before deploying.
5. **pgvector extension not enabled** — Run `CREATE EXTENSION IF NOT EXISTS vector;` on Render DB. Already provisioned but extension NOT yet enabled.
6. **Render cold starts** — UptimeRobot on /health every 5 minutes. Set up before demo.
7. **Gemini 429 rate limit** — 10 RPM on generation. Handle with try/except. Never crash app.
8. **Spider chart empty state** — Handle case where quiz hasn't been taken yet. Show placeholder with instructions.
